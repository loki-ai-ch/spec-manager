# 方法论文档可信度加固设计 — 技术设计

## 方案概述

本设计以 `methodology-hardening-L1` 为边界，只修订公开方法论文档及其专项回归测试，不改变运行时行为，也不代替 `lifecycle-guidance-sync-L1` 对其他入口文件的生命周期同步工作。

方法论文档重构为三类信息：

```
[规范性契约]
  状态流 + 门禁分级 + 例外路径 + 完成定义
          │
          v
[运行机制]
  分层约束 + 验证证据 + 失败上下文 + 审计
          │
          v
[设计理念与边界]
  价值说明 + 当前能力/目标能力 + 实践启发 + 适用场景
```

专项回归测试只检查能够稳定字面判定的关键事实，防止已识别的强表述、错误状态机和过时基线重新出现。

## 技术决策

| 问题 | 候选选项 | 用户选择 | 选定理由 |
|---|---|---|---|
| 文档改造范围 | A: 仅方法论文档 B: 同步所有入口文档 | A | 本 L1 聚焦方法论真实性；跨入口生命周期同步已有独立 L1 |
| 信息架构 | A: 保持当前顺序局部修补 B: 按契约/机制/理念重排 | B | 让读者先看到系统保证，再理解机制和价值 |
| 能力表述方式 | A: 统一使用原则性描述 B: 显式区分 hard gate/warning/人工审核/目标能力 | B | 防止把提示和愿景误认为系统保证 |
| 状态机表达 | A: 单一统一图 B: L1/L2、L3、Task 分图 | B | 三类对象的正常生命周期不同 |
| 外部案例处理 | A: 保留“方法论验证” B: 无来源时改为“实践启发” | B | 当前缺少可复核来源和实验边界 |
| 回归保护 | A: 仅人工审核 B: 新增专项文本测试 | B | 关键语义可稳定字面检查，适合自动防回归 |
| 测试承载位置 | A: shell 脚本 B: Vitest 文档契约测试 | B | 项目已有 Vitest 测试体系，可纳入 `npm test` |

## 受影响模块

| 模块/路径 | 变更类型 | 范围 | 测试策略 |
|---|---|---|---|
| 公开方法论文档 | 修改 | 重排信息架构；修正状态机、门禁分级、R8/quick、审计基线、失败重试和外部证据表述 | 人工复核 + 专项文档契约测试 |
| 文档契约测试 | 新增 | 检查关键正确事实存在、已知错误强表述不存在 | Vitest |

## 数据模型

无持久化数据或运行时 Schema 变更。

文档内部采用以下概念分类：

| 分类 | 含义 | 失败影响 |
|---|---|---|
| hard gate | CLI 或核心逻辑直接拒绝推进 | 阻止当前操作 |
| warning | 系统提示但不阻止推进 | 需要人工判断 |
| human gate | 必须由用户明确批准或审核 | Agent 不得自行推进 |
| target capability | 设计目标或未来增强方向 | 当前不构成系统保证 |

## 接口契约

### 方法论文档契约

方法论文档必须满足：

1. 使用独立状态流描述 L1/L2、L3 和 Task。
2. 门禁能力矩阵至少覆盖内容质量校验、计划校验、Task 步骤、verification、真实环境验收与 AC 覆盖。
3. 明确当前系统保留失败上下文并支持继续处理，但不承诺自动 retry 调度。
4. 明确新功能和非平凡工作走 L1 → L2 → L3 → Task；quick 是受限例外，R8 是代码调查规则。
5. 最低审计合规基线与当前系统一致。
6. 外部案例无可追溯来源时仅作为实践启发。

### 文档契约测试

专项测试读取方法论文档文本，并断言：

| 检查类型 | 契约 |
|---|---|
| 必须存在 | 分层状态流、门禁分类、quick 例外、包含 R18 的最低合规基线、实践启发标题 |
| 禁止存在 | “失败必然重试”、“每个模块必然被执行”、“方法论验证”等已知过度承诺 |
| 一致性 | L3 定位为实施规格或实施契约，Task 定位为执行记录 |

测试只覆盖稳定事实，不对完整中文段落做快照，避免正常编辑引发脆弱失败。

## 容错与降级

| 场景 | 影响 | 降级策略 | 恢复方式 |
|---|---|---|---|
| 文档已有未提交修改 | 可能覆盖用户新增内容 | 基于当前工作树增量编辑，不恢复原文件 | 对照 diff 逐段复核 |
| 生命周期同步规格后续修改同一段落 | 可能产生语义冲突 | 本设计只写正确目标语义，不修改其他入口 | 后续由 lifecycle-guidance-sync 复用该表述 |
| 测试过度依赖具体措辞 | 文案优化产生误报 | 仅断言关键标识和禁止强表述 | 调整为语义更稳定的匹配 |
| 外部案例未来获得可靠来源 | 当前“实践启发”表述偏保守 | 保留升级空间 | 提供来源与边界后另行评审升级结论 |

## 向后兼容

- **运行时行为**: 不变。
- **CLI**: 不变。
- **Spec/Task 数据**: 不变。
- **公开说明**: 纠正过度承诺和错误语义，属于兼容性文档修复。
- **未提交修改**: 必须保留当前方法论文档新增的约束闭环内容，仅修正和重组。

## 关键交互流程

```
读取当前方法论文档与规则/实现事实
  ├─ 标记 hard gate / warning / human gate / target capability
  ├─ 重写独立状态流与完成定义
  ├─ 修正失败处理、R8/quick、审计基线和外部案例
  ├─ 重排契约/机制/理念结构并去重
  └─ 执行文档契约测试 + 全量测试 + diff 复核
```

## 可观测性

- **测试信号**: 专项文档契约测试在关键错误表述回归时失败。
- **审查信号**: `git diff` 应显示文档语义修正和结构重排，不包含运行时代码行为变化。
- **验收信号**: 全量测试、lint、build 和 `git diff --check` 通过。
