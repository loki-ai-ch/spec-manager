# v0.4.0 — Methodology Enforcement and Distribution Consistency

## Highlights

- Enforces L3 verification commands and `@verify` rules before Task completion.
- Requires successful structured verification evidence and preserves failed-step context.
- Makes R18 transactional: confirmed L1 specs can pre-create decisions, and final completion requires an active decision card.
- Replaces broad `task complete --force` with scoped, reason-required bypasses that remain auditable without satisfying compliance.
- Detects and safely synchronizes drifted Claude and CodeBuddy managed assets.
- Adds complete installed-CLI `dist/` verification to prevent stale published executables.

## Added

- Verification layers (`compile`, `functional`, `smoke`) and grouped Task display.
- Machine-checkable `@verify` rules and L3 verification command execution.
- Managed Agent asset drift detection and `project agents --sync-managed`.
- Installed CLI verification through `npm run verify:installed-cli`.
- Methodology, verification, lifecycle, R18, and distribution regression tests.

## Changed

- L3 approval now freezes in one explicit approval.
- `decision create` accepts confirmed or implemented L1 specs.
- Only active decision cards satisfy R18; partial and superseded cards remain historical.
- Task completion checks frozen status, successful steps, and verification evidence before executing spec commands.
- Doctor guidance uses non-destructive managed-asset synchronization.
- Methodology and Agent instructions now distinguish hard gates, warnings, human gates, and target capabilities.

## Compatibility

- `task complete --force` is rejected. Use scoped `--skip-r18`, `--skip-verification`, or `--skip-verify` with `--reason`.
- Existing Task verification records without a layer are treated as `functional`.
